# 数学算术类型方案

## 1. 文档说明

- 文档名称：数学算术类型方案
- 版本：V1.0
- 日期：2026-10-26
- 目的：在现有「儿童学习助手」基础上新增「算术」类型，说明前后端实现与数据存储方案

## 2. 需求

1. 管理端（家长端）：设置算术的**最小值**、**最大值**，勾选运算符（加、减、乘、除），确认保存。
2. 答题端（孩子端）：根据家长设置的范围与运算符**随机出题**，孩子**手动输入答案**并判分。
3. 输出：前端方案、后端方案、数据存储方案。

## 3. 现状分析

当前系统内容类型为：`character`（汉字）、`classic`（国学）、`poem`（古诗）、`idiom`（成语）、`englishWord`（英语）。

现状特征：

- 五类内容均为「**内容驱动**」：家长录入内容 → 写入 `data/contents/*.json` → 会话从内容库抽样出题。
- 五种题型均已收敛为「**卡片**」题型（`*_card`），孩子点击「下一个」即视为已学习，不判分。
- `submit_answer` 接口仍保留（用于兼容旧的作答链路），可复用为算术判分入口。
- 学习规则 `learning_rules.json` 按孩子维度保存 `question_count`（每轮题量）、`default_content_types`（默认类型）、`allow_child_select_types`、`status`。

算术与现有类型的关键差异：

| 维度     | 现有类型                      | 算术                      |
| -------- | ----------------------------- | ------------------------- |
| 数据来源 | 内容条目（`contents/*.json`） | 规则参数（范围 + 运算符） |
| 出题方式 | 从内容库抽样                  | 按设置即时随机生成        |
| 作答方式 | 卡片（点击下一个，不判分）    | 输入答案（判分）          |
| 存储     | 每个内容一条记录              | 每个孩子一条设置记录      |

因此算术需要：新增一种「规则驱动」的内容类型、新增按孩子维度的算术设置存储、新增「数字输入」作答交互，并复用 `submit_answer` 判分。

## 4. 总体设计决策

1. 新增内容类型枚举 `math`（算术），但不落 `contents/*.json`（无具体内容条目）。
2. 新增按孩子维度的算术设置，独立存储到 `data/math_settings.json`（每个孩子一条有效记录）。
3. 新增题型 `math_arithmetic`，孩子端使用「数字输入框」作答，复用 `POST .../sessions/{session_id}/answers` 判分。
4. 管理端新增「算术设置」入口；答题端类型选择新增「算术」。
5. 算术题计入正确率（`answered_questions` / `correct_questions` / `accuracy_rate`）。

## 5. 数据存储方案

### 5.1 目录结构

```text
data/
  parent_users.json
  children.json
  learning_rules.json
  math_settings.json          # 新增：算术设置
  contents/
    character.json

    idiom.json
    englishWord.json
  sessions/
    learning_sessions.json
    session_questions.json
    answer_records.json
```

### 5.2 math_settings.json 结构

每个孩子最多一条有效记录（软删除后保留历史）。采用 upsert 语义：存在则更新，不存在则创建。

```json
[
  {
    "id": "uuid",
    "child_id": "uuid",
    "min_value": 1,
    "max_value": 20,
    "operators": ["add", "subtract", "multiply", "divide"],
    "status": 1,
    "created_at": "2026-10-26T10:00:00Z",
    "updated_at": "2026-10-26T10:00:00Z",
    "deleted_at": null,
    "is_deleted": 0
  }
]
```

字段说明：

| 字段       | 类型      | 可空 | 默认    | 说明                                         |
| ---------- | --------- | ---- | ------- | -------------------------------------------- |
| id         | str       | 否   | UUID    | 主键                                         |
| child_id   | str       | 否   | 无      | 关联孩子                                     |
| min_value  | int       | 否   | 0       | 最小值，≥ 0                                  |
| max_value  | int       | 否   | 20      | 最大值，> min_value                          |
| operators  | list[str] | 否   | ["add"] | 非空子集：add / subtract / multiply / divide |
| status     | int       | 否   | 1       | 是否启用算术，0/1                            |
| created_at | str       | 否   | now     | 创建时间（UTC）                              |
| updated_at | str       | 否   | now     | 更新时间（UTC）                              |
| deleted_at | str       | 是   | null    | 软删除时间                                   |
| is_deleted | int       | 否   | 0       | 软删除标记                                   |

运算符取值与展示符号：

| 枚举值   | 名称 | 符号 |
| -------- | ---- | ---- |
| add      | 加法 | `+`  |
| subtract | 减法 | `-`  |
| multiply | 乘法 | `×`  |
| divide   | 除法 | `÷`  |

约束：

- `0 ≤ min_value < max_value`
- `operators` 非空，且每个值 ∈ {add, subtract, multiply, divide}
- 同一孩子仅允许一条 `is_deleted = 0` 的有效设置

### 5.3 会话题目快照（session_questions.json 新增题型）

算术题 `content_id` 为 `null`（无内容条目），`content_snapshot` 保存本次出题参数，保证历史可追溯：

```json
{
  "id": "uuid",
  "session_id": "uuid",
  "content_id": null,
  "content_type": "math",
  "question_type": "math_arithmetic",
  "question_stem": "3 + 5 = ?",
  "question_options": [],
  "correct_answer": "8",
  "answer_explanation": "",
  "question_order": 1,
  "content_snapshot": {
    "min_value": 1,
    "max_value": 20,
    "operator": "add",
    "operand_a": 3,
    "operand_b": 5
  },
  "created_at": "2026-10-26T10:00:00Z",
  "updated_at": "2026-10-26T10:00:00Z",
  "deleted_at": null,
  "is_deleted": 0
}
```

## 6. 后端方案

### 6.1 模型（backend/app/models.py）

新增内容类型与领域模型：

```python
ContentType = Literal[
    "character", "classic", "poem", "idiom", "englishWord", "math"
]
MathOperator = Literal["add", "subtract", "multiply", "divide"]


class MathSettingsUpsert(BaseModel):
    min_value: int = Field(default=0, ge=0)
    max_value: int = Field(default=20, ge=1)
    operators: list[MathOperator] = Field(min_length=1)
    status: int = Field(default=1, ge=0, le=1)


class MathSettings(BaseModel):
    id: str
    child_id: str
    min_value: int
    max_value: int
    operators: list[MathOperator]
    status: int
    created_at: str
    updated_at: str
    deleted_at: str | None = None
    is_deleted: int = 0
```

说明：

- `math` 仅加入内容类型枚举，用于 `default_content_types` / `selected_content_types`，不进入 `list_contents` 的内容文件遍历列表。
- `operators` 支持 Pydantic 校验后，再在服务层校验 `min_value < max_value`（跨字段校验在服务层完成）。

### 6.2 服务层（backend/app/services/parent_service.py）

新增：

- `get_math_settings(parent_id, child_id) -> MathSettings | None`
- `upsert_math_settings(parent_id, child_id, payload: MathSettingsUpsert) -> MathSettings`

校验规则：

- 孩子不存在 → `LookupError`
- `min_value >= max_value` → `ValueError`（映射为 `42207`）
- `operators` 为空或含非法值 → `ValueError`（映射为 `42207`）

读写沿用 `JsonStore.read_list / write_list("math_settings.json")`，原子替换 + 文件级锁。

### 6.3 接口（backend/app/api/routers/）

新增 `math.py` 路由，前缀 `/children/{child_id}/math-settings`：

#### 6.3.1 获取算术设置

- `GET /api/v1/children/{child_id}/math-settings`
- 鉴权：是
- 返回：有效设置对象；未设置时 `data` 返回 `null`

#### 6.3.2 保存算术设置

- `PUT /api/v1/children/{child_id}/math-settings`
- 鉴权：是
- 请求体：

```json
{
  "min_value": 1,
  "max_value": 20,
  "operators": ["add", "subtract", "multiply", "divide"],
  "status": 1
}
```

- 语义：upsert（存在则更新，不存在则创建），成功返回设置对象。

### 6.4 出题规则（backend/app/services/learning_service.py）

`start_session` 扩展逻辑：

1. 确定 `selected_types`（来自请求或规则默认）。
2. 将 `selected_types` 拆分为 `content_types`（既有五类）与 `math`。
3. 若选中 `math`：
   - 读取该孩子的算术设置；不存在 / 已停用 → `40407`；参数非法 → `42207`。
   - 按 6.4.1 生成算术题。
4. 若同时选中内容类型，按 6.4.2 混合。

#### 6.4.1 单题生成

每道题：

1. 从 `operators` 随机选一个运算符。
2. 在 `[min_value, max_value]` 内生成操作数，保证结果非负且除法整除：

| 运算符   | 生成规则                                             | 结果                |
| -------- | ---------------------------------------------------- | ------------------- |
| add      | a, b ∈ [min, max]                                    | a + b               |
| subtract | a, b ∈ [min, max]，若 a < b 则交换                   | a - b               |
| multiply | a, b ∈ [min, max]                                    | a × b               |
| divide   | b ∈ [max(1, min), max]，商 q ∈ [min, max]，a = b × q | q（整除、非负整数） |

3. `question_stem = f"{a} {symbol} {b} = ?"`，符号取自映射（+、-、×、÷）。
4. `correct_answer = str(result)`，`question_options = []`，`content_id = null`。
5. `content_snapshot` 记录 `{min_value, max_value, operator, operand_a, operand_b}`。

#### 6.4.2 题量分配

总题量仍为 `rule.question_count`：

- 仅选 `math`：全部生成算术题。
- `math` 与其他内容类型同时选中：按选中类型数均分（向下取整，且 `math` 至少 1 题），其余题量由内容类型抽样补齐；内容不足时用算术题补足，避免不足 `question_count`。

### 6.5 判分与作答

复用 `submit_answer`，为 `math_arithmetic` 增加数字校验：

```python
if question.get("question_type") == "math_arithmetic":
    try:
        user_value = int(payload.user_answer.strip())
    except ValueError:
        raise LearningError(422, 42208, "answer must be an integer")
    is_correct = user_value == int(question["correct_answer"])
else:
    # 既有逻辑（选项校验 / 卡片不经过此入口）
    ...
```

作答后写入 `answer_records.json`（`content_id` 为 null、`content_type` 为 `math`），并更新会话的 `answered_questions` / `correct_questions` / `accuracy_rate`。

### 6.6 错误码

| 错误码 | 含义                                         |
| ------ | -------------------------------------------- |
| 40407  | 算术设置不存在                               |
| 42207  | 算术设置不合法（min ≥ max、运算符为空/非法） |
| 42208  | 答案必须是整数                               |

沿用既有错误码：`40402` 孩子不存在、`40405` 会话不存在、`40406` 题目不存在、`40903` 会话状态冲突等。

### 6.7 统计影响

- 算术题作答后进入 `answer_records`，`stats_overview` 的平均正确率、`stats_by_content_type` 的 `math` 正确率均正常统计。
- `stats_weak_contents`（薄弱内容项）依赖 `content_id` 映射具体内容，算术无具体内容，故不出现在薄弱内容项中（文档明确为预期行为）。

## 7. 前端方案

### 7.1 类型（frontend/src/types/api.ts）

```ts
export type ContentType =
  | "character"
  | "classic"
  | "poem"
  | "idiom"
  | "englishWord"
  | "math";

export type MathOperator = "add" | "subtract" | "multiply" | "divide";

export type MathSettings = {
  id: string;
  child_id: string;
  min_value: number;
  max_value: number;
  operators: MathOperator[];
  status: number;
  created_at: string;
  updated_at: string;
};

export type MathSettingsPayload = {
  min_value: number;
  max_value: number;
  operators: MathOperator[];
  status: number;
};
```

`SessionQuestion.question_type` 已是 `string`，无需改动。

### 7.2 API（frontend/src/api/math.ts，新增）

```ts
export function getMathSettings(token, childId): Promise<MathSettings | null>;
export function updateMathSettings(
  token,
  childId,
  payload: MathSettingsPayload,
): Promise<MathSettings>;
```

分别调用 `GET` / `PUT /children/{childId}/math-settings`。

### 7.3 管理端（ParentDashboard.tsx）

1. `CONTENT_TYPE_OPTIONS` 增加 `{ label: "算术", value: "math" }`（用于学习规则 `default_content_types` 与内容类型选项）。
2. 在「学习规则」或新增「算术设置」卡片中提供表单：
   - 最小值 `InputNumber`（min 0）
   - 最大值 `InputNumber`（min 1）
   - 运算符 `Checkbox.Group`：加法 `+` / 减法 `-` / 乘法 `×` / 除法 `÷`
   - 启用 `Switch`
   - 「保存」按钮 → `updateMathSettings`，成功后 `message.success`
3. 进入时用 `getMathSettings` 回填，未设置则显示默认值。

说明：`math` 无内容条目，因此不出现在「学习内容管理」列表，也不参与批量导入。

### 7.4 答题端（ChildLearning.tsx）

1. 类型选择 `CONTENT_TYPES` 增加 `{ value: "math", label: "算术", mark: "算" }`。
2. 新增「数字输入」渲染分支：当 `question_type === "math_arithmetic"` 时：
   - 题干显示 `question_stem`（如 `3 + 5 = ?`）。
   - 渲染数字输入框（`InputNumber` 或 `Input type=number`）+「提交答案」按钮。
   - 提交后复用 `submitAnswer`，反馈条显示「答对了 / 再记一记」与「正确答案：8」。
3. 该分支区别于「卡片」分支（`CARD_QUESTION_TYPES`）与既有选择题分支。

交互要求（儿童友好）：

- 输入框大字号、只允许数字
- 提交按钮大而清晰
- 正确/错误反馈沿用现有 `feedback-strip` 样式

## 10. 不改动项与约定

- 既有五种内容类型及其卡片作答方式保持不变。
- `list_contents` / 「学习内容管理」不处理 `math`（无内容条目）。
- `stats_weak_contents` 不包含算术（无 `content_id`），为预期行为。
- 会话题目总题量始终受 `rule.question_count` 约束；混合类型的均分规则见 6.4.2，作为 MVP 约定，后续可改为更精细的配比配置。

## 11. 结论

本方案在不大幅改动既有架构的前提下，通过「新增 `math` 内容类型 + `math_settings.json` 设置存储 + `math_arithmetic` 题型 + 复用 `submit_answer` 判分」，实现了「家长设置范围与运算符 → 孩子随机出题并输入答案」的完整闭环，符合 MVP 低复杂度、强可控、快速交付的目标。
