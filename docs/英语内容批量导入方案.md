# “英语”内容批量导入方案

> 参考“汉字”批量导入逻辑，改造“英语单词”类型的新建方式。

## 一、需求

1. 将“英语单词”类型改名为“英语”，新建时**去掉“标题”输入**。
2. 正文支持多行，保存时**按换行、标点符号分割成多条记录**（空格不分割，空格分隔的词组作为整体保留）。

## 二、现状分析

- 内容类型枚举值仍为 `englishWord`（`backend/app/models.py`、`frontend/src/types/api.ts`），仅展示名称为“英语单词”。
- “汉字”已有批量导入能力：
  - 后端：`POST /children/{child_id}/contents/characters/batch`，`CharacterBatchCreate` 模型，`ParentService.batch_upsert_characters()`，`_extract_characters()` 按单字去重。
  - 前端：`batchUpsertCharacters()` API，新建弹窗中“汉字”类型隐藏标题、正文按单字导入。
- “英语单词”目前走普通 `create_content` 单条创建，需要标题。

## 三、修改方案

### 1. 后端

#### 1.1 模型（`backend/app/models.py`）

新增 `EnglishBatchCreate`（与 `CharacterBatchCreate` 结构一致，不含 `content_type`、`title`）：

```python
class EnglishBatchCreate(BaseModel):
    content_text: str = Field(min_length=1)
    pronunciation: str | None = Field(default=None, max_length=100)
    meaning: str | None = Field(default=None, max_length=255)
    example: str | None = Field(default=None, max_length=255)
    difficulty: int = Field(default=1, ge=1, le=3)
    status: ContentStatus = "enabled"
    sort_order: int = 0
    detail: dict[str, Any] = Field(default_factory=dict)
```

#### 1.2 服务（`backend/app/services/parent_service.py`）

新增 `batch_upsert_english_words()`，逻辑与 `batch_upsert_characters()` 对齐：

- 用 `_extract_english_words()` 从 `content_text` 中按换行与标点切分（空格不分割，空格分隔的词组作为整体保留），并保留单词内部的连字符/撇号（如 `well-known`、`don't`），再按词组去重。
- 每个词组作为一条记录，`title = content_text = 词组`。
- 按词组 upsert：已存在则保留 ID 并覆盖公共属性，否则新建。
- 写入 `contents/englishWord.json`。

新增静态方法：

```python
@staticmethod
def _extract_english_words(content_text: str) -> list[str]:
    words: list[str] = []
    seen: set[str] = set()
    for token in re.findall(r"[A-Za-z0-9 '’-]+", content_text):
        word = token.strip()
        if word and not word.isdigit() and word.lower() not in seen:
            seen.add(word.lower())
            words.append(word)
    return words
```

说明：正则 `[A-Za-z0-9 '’-]+` 匹配由字母/数字、空格、连字符、撇号构成的连续片段，因此换行、逗号、句号、感叹号等标点都会作为切分符，而**空格不会分割**（如 `good morning` 作为整体保留）；片段首尾的空格会被去除；纯数字片段被忽略；按首次出现顺序去重（忽略大小写），保留原始大小写。

#### 1.3 路由（`backend/app/api/routers/contents.py`）

新增批量接口（与 `characters/batch` 平行）：

```
POST /children/{child_id}/contents/english/batch
```

请求体为 `EnglishBatchCreate`，成功返回 `list`、`created_count`、`updated_count`、`total_count`；正文无单词时返回 `42206`。

### 2. 前端

#### 2.1 类型与 API（`frontend/src/types/api.ts`、`frontend/src/api/contents.ts`）

- 复用 `CharacterBatchPayload`（即 `Omit<ContentPayload, "content_type" | "title">`）作为英语批量请求体。
- 新增 `batchUpsertEnglishWords()`，调用 `/children/{childId}/contents/english/batch`。

#### 2.2 家长端弹窗（`frontend/src/features/parent/pages/ParentDashboard.tsx`）

- `CONTENT_TYPE_OPTIONS` 中 `englishWord` 的 label 由“英语单词”改为“英语”。
- 定义批量类型判断：`character` 与 `englishWord` 均视为批量类型。
- 新建时（非编辑）批量类型隐藏“标题”输入，类型选择占满整行。
- 正文标签/提示/占位符按类型区分：
  - 汉字：`汉字正文`，提示“按单字去重导入”。
  - 英语：`英语正文`，提示“按换行、标点分割（空格不分割），按词组去重导入”。
- 提交逻辑：`englishWord` 走 `batchUpsertEnglishWords()`，成功提示“已新增 X 个单词，更新 Y 个单词”。

#### 2.3 孩子端（`frontend/src/features/child/pages/ChildLearning.tsx`）

- 该处 `englishWord` 的 label 已是“英语”，无需改动。
