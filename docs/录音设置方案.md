# 录音设置方案

## 1. 需求

管理端（家长端）新增「录音设置」，为**每种可录音的答题类型**（汉字、英语、成语、拼音）单独设置：

1. 是否开启录音功能（`enabled`）；
2. 是否自动结束（`auto_stop`）；
3. 自动结束时长（`auto_stop_seconds`，秒）。

## 2. 现状

- 学习端四类卡片（`character_card`、`english_word_card`、`idiom_card`、`pinyin_card`）已提供「录音」按钮（见 `RECORDABLE_CARD_QUESTION_TYPES`）。
- 录音逻辑集中在 `ChildLearning.handleToggleRecord`：点击开始 `recognition.start()`，再次点击 `recognition.stop()`，识别后判分。
- 目前录音功能对所有四类**固定开启、手动结束、无时长限制**，管理端不可配置。
- 本项目已有「朗读设置」的完整实现范式（`ReadingSettings` 按 child 存储、每类型独立字段、家长端 Tab、孩子端按类型取值），本方案完全对齐该范式。

## 3. 数据方案

- 存储文件：`backend/data/recording_settings.json`（JSON 列表，每个孩子一条，模式同 `reading_settings.json`）。
- 数据维度：按 `child_id` 存储。
- 字段（4 类 × 3 项 + status）：

| 字段                                                                  | 含义                   | 类型 | 默认         | 范围 |
| --------------------------------------------------------------------- | ---------------------- | ---- | ------------ | ---- |
| `character_enabled`                                                   | 汉字是否开启录音       | bool | true         | —    |
| `character_auto_stop`                                                 | 汉字是否自动结束       | bool | false        | —    |
| `character_auto_stop_seconds`                                         | 汉字自动结束时长（秒） | int  | 5            | 1~30 |
| `english_enabled` / `english_auto_stop` / `english_auto_stop_seconds` | 英语                   | 同上 | true/false/5 | —    |
| `idiom_*`                                                             | 成语                   | 同上 | true/false/5 | —    |
| `pinyin_*`                                                            | 拼音                   | 同上 | true/false/5 | —    |
| `status`                                                              | 是否启用               | int  | 1            | 0/1  |

- 新建孩子时自动初始化默认录音设置（`_init_child_defaults`）。

## 4. 后端方案

- `models.py`：新增 `RecordingSettingsUpsert`（写入载荷）与 `RecordingSettings`（存储模型）。
- `parent_service.py`：新增常量 `DEFAULT_AUTO_STOP_SECONDS = 5`，`get_recording_settings` / `upsert_recording_settings`，并在新建孩子时写入默认值。
- 新增路由 `api/routers/recording.py`：
  - `GET /children/{child_id}/recording-settings`（无记录返回 `null`）。
  - `PUT /children/{child_id}/recording-settings`（upsert）。
- `main.py` 注册该路由。

## 5. 前端方案

### 5.1 家长端

- `ParentDashboard` 新增「录音设置」Tab：四个类型分组，每组三个控件：
  - 「开启录音」`Switch`；
  - 「自动结束」`Switch`；
  - 「自动结束时长」`InputNumber`（1~30 秒，`auto_stop` 关闭时禁用）。
- 新增 `api/recording.ts`：`getRecordingSettings` / `updateRecordingSettings`。

### 5.2 孩子端

- 加载录音设置（类似朗读设置加载），新增 state `recordingSettings`。
- `speech.ts` 新增纯函数 `getRecordConfig(contentType, settings)`，返回 `{ enabled, autoStop, seconds } | null`，设置缺失时回退默认（全部开启、手动结束、5 秒）。
- 录音逻辑改造（`handleToggleRecord`）：
  1. 录音按钮展示条件：`RECORDABLE_CARD_QUESTION_TYPES 命中 && config.enabled`。
  2. 点击开始后，若 `config.autoStop` 为真，用 `setTimeout` 在 `config.seconds` 秒后自动 `recognition.stop()`（用 `useRef` 保存定时器）。
  3. 结束/切题/卸载/再次点击时清除定时器。

## 6. 录音逻辑细节

```ts
function handleToggleRecord() {
  const config = getRecordConfig(question.content_type, recordingSettings);
  if (!config?.enabled) return;

  if (isRecording) {
    recognitionRef.current?.stop();
    clearAutoStopTimer();
    return;
  }

  recognition.start();
  setIsRecording(true);
  if (config.autoStop) {
    autoStopTimerRef.current = window.setTimeout(() => {
      recognitionRef.current?.stop();
    }, config.seconds * 1000);
  }
}
```

- 识别语言沿用现有 `getSpeechLanguage`（英语 `en-US`、其余 `zh-CN`）。
- 判分沿用现有逻辑（汉字/英语/成语前端比对，拼音走后端 `judge_speech`）。

## 7. 兼容与默认

- 旧数据无 `recording_settings.json`：查询返回 `null`，孩子端回退默认（四类开启、手动结束、5 秒），行为与现状一致。
- `enabled=false` 的类型：孩子端不显示录音按钮（朗读按钮不受影响）。

## 8. 测试方案

### 8.1 后端

- `RecordingSettings` 默认值与 `ge/le` 校验。
- `get/upsert_recording_settings` 读写与新建孩子默认初始化。

### 8.2 前端

- `getRecordConfig` 按类型取配置、缺省回退。
- 录音按钮在 `enabled=false` 时不渲染、其余类型正常渲染。
- mock `SpeechRecognition`：`autoStop` 开启时，经过 `seconds` 秒自动触发 `stop`（用 fake timers 验证）；关闭时不自动停止。
- 家长端「录音设置」Tab 保存后调用 `updateRecordingSettings`。

## 9. 实施范围

- 后端：模型、服务、路由、默认初始化（零破坏，新增文件 `recording_settings.json`）。
- 前端：家长端 Tab + 孩子端录音逻辑改造 + 纯函数与测试。
- 不改变现有朗读设置、判分逻辑与数据结构。
