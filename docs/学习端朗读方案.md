# 学习端朗读功能方案

## 1. 文档说明

- 文档名称：学习端朗读功能方案
- 版本：V1.0
- 日期：2026-10-30
- 目的：为学习端「汉字、国学、古诗、成语、英语」五类卡片增加「朗读」按钮，点击朗读该卡片全部内容

## 2. 需求

1. 学习端（孩子端）在「汉字、国学、古诗、成语、英语」五类卡片上提供「朗读」按钮。
2. 点击按钮，朗读该卡片当前展示的全部内容（单字/成语/单词/整首诗/整组国学）。
3. 算术（math）与拼音（pinyin）类型不在本次范围内。

## 3. 现状

- 五类均为「内容驱动 + 卡片」题型：`character_card`、`classic_card`、`poem_card`、`idiom_card`、`english_word_card`。
- 卡片通过 `question_stem` 展示内容；汉字/国学/古诗/成语已额外返回 `question_pinyin`（逐字拼音）。
- 目前无任何语音朗读能力。

## 4. 技术选型

### 方案 A（推荐）：浏览器 Web Speech API

- 使用浏览器内置 `window.speechSynthesis` + `SpeechSynthesisUtterance`。
- 优点：零后端改动、零存储、零依赖、跨平台（Chrome / Edge / Safari 等支持）。
- 语言：汉字/国学/古诗/成语使用 `zh-CN` 语音，英语使用 `en-US` 语音。
- 限制：
  - 受浏览器自动播放策略限制，必须由用户点击触发（本需求天然满足）。
  - 发音质量取决于系统/浏览器是否安装了对应语言语音包；无可用语音时按钮禁用。

### 方案 B（备选）：后端 TTS

- 后端调用云 TTS 或本地 TTS 引擎生成音频，返回音频流或缓存音频文件。
- 缺点：需要新增后端接口、音频文件/缓存存储、网络与成本开销，MVP 不推荐。

**结论：采用方案 A（Web Speech API），不引入后端 TTS。**

## 5. 朗读内容（朗读文本）

朗读文本 = 卡片当前内容，优先使用「干净的朗读文本」，避免读出书名号、间隔号等装饰符号。

| 类型 | 朗读内容                  | 朗读文本                                        |
| ---- | ------------------------- | ----------------------------------------------- |
| 汉字 | 单字                      | `question_stem`（该字本身）                     |
| 成语 | 成语                      | `question_stem`（成语）                         |
| 英语 | 单词                      | `question_stem`（单词）                         |
| 国学 | 整组（上句 + 下句）       | `question_stem`（换行转为停顿）                 |
| 古诗 | 诗名 + 朝代 + 诗人 + 全文 | `question_stem` 清洗后（去《》、·，换行转停顿） |

清洗规则（针对古诗等含装饰符号的内容）：

- 去掉 `《`、`》`、`·` 等非语音符号。
- 换行 `\n` 转为停顿（空格或逗号），避免连读。
- 保留标点（，。！？）作为自然停顿。

汉字朗读说明：默认识字（TTS 发音），多音字可能按默认读音朗读；如需更精确，可选读 `question_pinyin`（拼音），作为后续可配置项。

## 6. 数据存储方案

- **方案 A 下不新增任何存储文件**。朗读文本由已有的 `question_stem`（已写入 `session_questions.json`）就地清洗得到。
- 若采用「后端提供干净朗读文本」的增强方式，可在会话题目快照 `session_questions.json` 中新增字段 `read_text`（与 `question_stem`、`question_pinyin` 并列），仍不新增文件：

```json
{
  "question_stem": "《静夜思》唐·李白\n床前明月光\n疑是地上霜",
  "question_pinyin": ["…"],
  "read_text": "静夜思 唐 李白 床前明月光 疑是地上霜"
}
```

推荐首版**不加 `read_text`**，由前端就地清洗，保持后端与存储零改动。

## 7. 前端方案

### 7.1 朗读按钮

- 位置：卡片题干区域（`question-kind` 旁或题干下方），使用 `SoundOutlined`（或「朗读」文字）按钮。
- 展示范围：仅 `character_card`、`classic_card`、`poem_card`、`idiom_card`、`english_word_card` 五类；`math_arithmetic`、`pinyin_card` 不展示。

### 7.2 朗读逻辑

- 点击时：
  1. 由 `content_type` 选择语音语言：`englishWord → en-US`，其余 → `zh-CN`。
  2. 计算朗读文本（对 `question_stem` 清洗）。
  3. 构造 `SpeechSynthesisUtterance` 并 `speechSynthesis.speak()`。
- 交互细节：
  - 再次点击可停止当前朗读（`speechSynthesis.cancel()`）。
  - 切换题目 / 完成学习 / 离开学习页时停止朗读。
  - 无可用的目标语言语音时禁用按钮。

### 7.3 组件与类型

- 无需后端 API；朗读文本清洗逻辑封装为纯函数 `toReadText(stem, contentType)`。
- `SessionQuestion` 类型无需改动（复用 `question_stem`）。

## 8. 后端方案

- 首版（方案 A）：后端**零改动**。
- 可选增强：若希望前端完全不做清洗，可在出题时（`learning_service._build_question`）为五类卡片生成 `read_text` 字段写入题目快照，逻辑与 `question_pinyin` 生成方式一致。

## 9. 测试方案

### 9.1 前端

- 朗读按钮在五类卡片上渲染、在 math/pinyin 卡片上不渲染。
- 点击朗读按钮调用 `speechSynthesis.speak`（mock），且 `utterance.lang` 与 `content_type` 匹配（英语 `en-US`，其余 `zh-CN`）。
- `toReadText` 清洗规则：去《》、·、换行转停顿。
- 再次点击触发 `cancel`。

### 9.2 后端

- 首版无后端改动，故无新增后端用例；若后续增加 `read_text`，补充对应断言。

## 10. 风险与约定

- 浏览器自动播放策略：必须由点击触发，符合本需求；需处理 `speechSynthesis` 未就绪的兼容场景。
- 语音包缺失：目标语言无语音时按钮禁用，避免点击无反馈。
- 多音字：TTS 发音可能与 `question_pinyin` 标注不一致，属已知限制（可视化拼音已兜底）。
- 本方案为「纯前端增强」，不引入后端 TTS、不新增存储，符合 MVP 低复杂度原则。
