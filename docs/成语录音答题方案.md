# 成语录音答题方案

## 1. 需求

为学习端（孩子端）的「成语」学习增加录音答题：

1. 成语卡片提供「录音」按钮，点击开始录音，再次点击结束录音。
2. 识别录音内容，与题目成语比对。
3. 给出「是否正确」的结果反馈。

## 2. 现状分析

- 成语题型为 `idiom_card`（卡片题），`question_stem` 即成语本身（如「地大物博」），可选带逐字拼音。
- 当前成语卡片无作答：点击「下一个」即调用 `mark_card_viewed` 记录「已学习」，不计入正确率。
- 卡片已有「朗读」按钮（Web Speech API `speechSynthesis`）。
- 本项目朗读功能采用「纯前端、零后端、零存储」策略，本次录音识别可延续同一思路。

## 3. 方案选型

### 3.1 录音

| 方案                                | 说明                                                                                | 结论             |
| ----------------------------------- | ----------------------------------------------------------------------------------- | ---------------- |
| MediaRecorder                       | `getUserMedia` 采集麦克风 + `MediaRecorder` 录成音频 blob，用于「上传后端识别」场景 | 后端识别方案使用 |
| SpeechRecognition（浏览器内置 ASR） | 内部自带采集与识别，点击 start/stop 即可，无需手动录制成文件                        | 纯前端方案使用   |

### 3.2 语音识别（ASR）

| 方案                                                  | 优点                                   | 缺点                                              | 结论         |
| ----------------------------------------------------- | -------------------------------------- | ------------------------------------------------- | ------------ |
| **A. Web Speech API `SpeechRecognition`（推荐 MVP）** | 零后端、零存储、零成本，与朗读方案对称 | 仅 Chrome/Edge 支持好、需联网、识别走浏览器厂商云 | **首版采用** |
| B. 后端云 ASR（讯飞/百度/阿里/腾讯/Azure）            | 准确率高、跨浏览器稳定、可记录         | 需密钥与网络成本、后端新增音频处理                | 增强备选     |
| C. 后端本地 ASR（Whisper）                            | 无云依赖、隐私好                       | 模型大、算力重，不适合轻量 MVP                    | 暂不采用     |

**结论：首版采用方案 A（纯前端 SpeechRecognition，零后端）；文档同时给出后端增强方案（方案 B）供后续升级。**

## 4. 推荐方案（MVP，纯前端）

复用朗读的交互范式：同一个「录音」按钮点击切换「开始 / 停止」。

### 4.1 前端组件与状态

在 `ChildLearning.tsx` 成语卡片（`idiom_card`）的 `question-head` 区，朗读按钮旁新增「录音」按钮：

```tsx
const [isRecording, setIsRecording] = useState(false);
const [speechResult, setSpeechResult] = useState<{
  transcript: string;
  isCorrect: boolean;
} | null>(null);
```

### 4.2 录音识别流程

```ts
// 浏览器兼容
const SR = window.SpeechRecognition || window.webkitSpeechRecognition;

function toggleRecord() {
  if (!SR) {
    message.error("当前浏览器不支持语音识别");
    return;
  }
  if (isRecording) {
    recognition.stop(); // 结束识别（等同于结束录音）
  } else {
    recognition.lang = "zh-CN";
    recognition.continuous = false;
    recognition.interimResults = false;
    recognition.start(); // 开始识别（等同于开始录音）
    setIsRecording(true);
  }
}

recognition.onresult = (e) => {
  const transcript = e.results[0][0].transcript;
  const correct =
    normalize(transcript) === normalize(currentQuestion.question_stem);
  setSpeechResult({ transcript, isCorrect: correct });
  setIsRecording(false);
};
recognition.onerror = (e) => {
  setIsRecording(false);
  message.error(mapError(e.error)); // not-allowed / no-speech / network ...
};
```

### 4.3 判分规则

- 归一化函数 `normalize(text)`：去首尾及中间空白、去标点（，。！？、空格）、全角字母转半角、忽略大小写。
- 归一化后的识别文本 == 归一化后的成语 → 正确，否则错误。
- 成语为四字（如「地大物博」），识别可能产生同音字误差；首版采用严格字符串比对，后续可扩展「拼音比对」容错（将识别文本转拼音再与 `question_pinyin` 比对）。

### 4.4 结果展示

- 正确：绿色提示「读对了！」+ 识别文本。
- 错误：红色提示「再试一次，正确答案：地大物博」+ 识别文本。
- 判分结果仅即时反馈，**不改变成语卡片性质**（仍点击「下一个」完成，不计入正确率）。

## 5. 后端增强方案（方案 B，可选）

当需要更高识别准确率、跨浏览器稳定、或将判分计入学习统计时，引入后端 ASR：

### 5.1 接口

`POST /api/v1/children/{child_id}/sessions/{session_id}/questions/{question_id}/speech`

- 请求：`multipart/form-data`，音频文件字段 `audio`（WebM/Opus，或前端转 WAV）。
- 响应：`{ transcript: string, is_correct: bool, correct_answer: string }`。

### 5.2 后端处理

1. 校验 session/question 归属与题型为 `idiom_card`。
2. 调用云 ASR（讯飞/百度/阿里等）识别文本。
3. 归一化比对 `question_stem`，计算 `is_correct`。
4. （可选）写入 `answer_records.json`，新增字段 `answer_type: "speech"`、`user_answer`=识别文本、`is_correct`，并像选择题一样更新 session 的 `answered_questions` / `correct_questions` / `accuracy_rate`。

### 5.3 新增模型

```python
class SpeechSubmit(BaseModel):
    session_question_id: str

class SpeechFeedback(BaseModel):
    session_question_id: str
    transcript: str
    is_correct: bool
    correct_answer: str
```

## 6. 风险与限制

| 风险         | 说明                                                                                       | 应对                                    |
| ------------ | ------------------------------------------------------------------------------------------ | --------------------------------------- |
| 浏览器支持   | SpeechRecognition 仅 Chrome/Edge 稳定，Firefox 不支持，Safari 需 `webkitSpeechRecognition` | 无支持时按钮禁用并提示                  |
| 联网依赖     | Chrome 识别走 Google 云                                                                    | 无网络时 `onerror` 提示                 |
| 麦克风权限   | 需用户授权，且需 HTTPS 或 localhost                                                        | `onerror` 的 `not-allowed` 给出引导提示 |
| 识别准确率   | 童声/环境噪声可能误识别，同音字误差                                                        | 首版严格比对，后续可加拼音容错          |
| 自动播放策略 | 识别需用户点击触发（本需求天然满足）                                                       | —                                       |

## 7. 测试方案

### 7.1 前端

- 成语卡片渲染「录音」按钮；非成语卡片不渲染。
- 点击「录音」→ `recognition.start` 且按钮变为「停止」；再次点击 → `recognition.stop`。
- mock `onresult` 返回正确/错误文本，断言判分结果展示正确。
- mock `onerror`（not-allowed 等），断言给出对应提示。

### 7.2 后端（仅增强方案）

- mock 云 ASR，断言音频上传接口返回识别文本与正确判分。
- 断言判分结果正确写入 `answer_records` 并更新正确率。

## 8. 实施范围

- **首版（本方案推荐）**：仅前端改动，新增录音按钮 + SpeechRecognition + 判分展示，后端零改动。
- **增强（后续）**：新增后端 ASR 接口与判分记录，前端改为上传音频。
